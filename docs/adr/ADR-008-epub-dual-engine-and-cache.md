# ADR-008: EPUB 毫秒级双引擎架构与正文 LRU 缓存池

## 上下文
EPUB 格式本质为 Zip 压缩包，内部包含 `content.opf`、`toc.ncx` / `nav.xhtml`、样式表及多章节 XHTML。若每次翻章或打开书籍都全量解包流，会导致数十兆大文件打开缓慢、内存飙升甚至 OOM。

## 决策
1. **双引擎架构**：
   - **本地随机访问引擎**：基于 `java.util.zip.ZipFile` 实现 $O(1)$ 随机条目寻址，快速抽取元数据与单章 HTML，避免全量解包。
   - **动态流式引擎**：针对 SAF 传入的未落地流或单向 InputStream，采用高效的单趟流式索引扫描。
2. **正文 LRU 缓存池**：
   - 内存中维护大小为 32 的 LinkedHashMap LRU 缓存池；
   - 章节在后台预热解析并纯文本化，前后翻章实现 0ms 闪电直出。
3. **多规范兼容**：支持 EPUB 2（NCX）、EPUB 3（HTML5 Nav）以及缺失目录时的 Spine 线性回退自动推导。

## 后果
- 正面：大文件（数十兆带插图 EPUB）秒级打开，翻章零卡顿。
- 正面：内存占用保持在 15MB 以内，符合手表严苛的内存配额要求。
- 负面：针对极少数损坏或非标 EPUB 包，需要持续增强容错回退机制。
