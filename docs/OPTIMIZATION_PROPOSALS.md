# WatchReader 体验与架构进阶优化规划设计文档

## 概述

WatchReader 是一款专为 466x466 纯圆屏智能手表（Android / Wear OS，如 OPPO Watch X / X2 系列）深度定制的极简本地电子书阅读器。
基于 Jetpack Compose + 原生 AndroidView 极速单 TextLayout 混合架构，目前已实现毫秒级 EPUB/TXT 流式解析、0 GC 自动平滑滚屏、OPPO 原厂 302 齿轮波形线性马达表冠滤波、极轻量局域网 Wi-Fi 传书及双轨极暗调光等核心能力。

本文档系统归档后续版本的产品交互、阅读排版、格式解析、硬件能效与代码架构全景优化方案，重点包含圆屏横向内边距与侧边栏联动几何推导，为后续版本迭代提供明确技术路径。

## 核心专题调研：圆屏横向内边距（Padding）与侧边栏联动

### 1. 屏幕几何空间约束

以常见的 466x466 分辨率、320 DPI（`density = 2.0`）智能手表为例：
- 屏幕物理直径：466 px（逻辑像素 233 dp）。
- 屏幕圆心：$(cx, cy) = (233, 233)\text{ px} = (116.5, 116.5)\text{ dp}$。
- 圆形屏幕内接正方形边长：$W_{in} = 2 \times R \times \cos(45^\circ) \approx 329.5\text{ px} \approx 164.8\text{ dp}$。
- 四角极限避让边距：$(466 - 329.5) / 2 \approx 68.3\text{ px} \approx 34.1\text{ dp}$。

### 2. 当前布局数据流与空间测算

- **正文阅读器区域（ReaderScreen）**：
  - 横向 Padding：`24 dp`（48 px）。
  - 正文排版横向区间：$[48\text{ px}, 418\text{ px}]$，有效文本宽度为 $370\text{ px} (185\text{ dp})$。
  - 纵向 Padding：顶部 `52 dp`（避让弧形章节名与顶部表圈），底部 `56 dp`（避让下表圈与翻章/自动滚屏胶囊）。
  - 顶部羽化遮罩 `48 dp`，底部羽化遮罩 `36 dp`，确保在垂直滚屏时，四角文字在进入裁切危险区前已平滑羽化消失。
- **侧边状态栏区域（CurvedSideStatusBar）**：
  - 贴边半径：$arcRadius = R - insetPx = 233 - 12 = 221\text{ px}$。
  - 9 点钟方向（电量）：横向占据区间约为 $[0, 22\text{ px}] = [0, 11\text{ dp}]$。
  - 3 点钟方向（时间）：横向占据区间约为 $[444\text{ px}, 466\text{ px}] = [222\text{ dp}, 233\text{ dp}]$。
- **当前间距裕量（呼吸空间）**：
  - 正文左边缘（48 px）与电量右边缘（22 px）间距：$26\text{ px} (13\text{ dp})$。
  - 正文右边缘（418 px）与时间左边缘（444 px）间距：$26\text{ px} (13\text{ dp})$。
  - 结论：当前 24 dp 的设置在几何上处于“黄金呼吸区”，正文文字与两侧状态栏有明确的留白分隔，视觉清晰且无压迫感。

### 3. 横向内边距调整的风险与收益分析

如果将横向 Padding 从 24 dp 缩小至 18 dp 或 16 dp：
- **核心收益**：
  - 正文宽度由 185 dp 增加到 197~201 dp，每行可多容纳 1~2 个汉字（以 14 sp 字号计），对于长段落能有效减少总行数与翻页频次，提升小屏阅读吞吐量。
- **严重风险**：
  - **侧边冲突**：由于正文启用了中文两端平整对齐（`JUSTIFICATION_MODE_INTER_WORD`），正文最右侧字符强制顶格至边界。若 Padding 设为 16 dp（32 px），正文右边缘拓展到 434 px，与 3 点钟时间（444 px）之间的安全间距骤降至仅 $10\text{ px} (5\text{ dp})$！正文文字与侧边时间几乎黏连，产生强烈的视觉侵入与阅读干扰。
  - **对角线裁切**：在长文本滚动过程中，当文字到达靠近顶部或底部（约 $y < 120\text{ px}$ 或 $y > 346\text{ px}$）但未完全进入渐变遮罩时，16 dp 的边距会导致两端文字直接触碰甚至越过物理圆形外壳而被强行裁切半边字。

### 4. 推荐落地实施方案：双轨自适应模式与微光淡出

基于上述测算，建议采取“自适应双轨模式”而非单纯缩减边距：
1. **模式一：标准舒适模式（默认 24 dp）**：
   - 保持 24 dp 横向黄金安全区；
   - 侧边时间和电量常驻（透明度 0.85），间距舒展自然，适合大多数日常阅读场景。
2. **模式二：紧凑宽屏模式（16 dp）**：
   - 为追求最大屏效的用户提供可选档位；
   - **侧边栏联动策略**：
     - **微光淡出（推荐）**：在静止阅读 3 秒后，侧边时间和电量通过平滑过渡淡出至透明度 0.2 或完全隐去；当用户滑动屏幕、双击或转动物理表冠时，瞬间恢复可见。既彻底释放了两侧 26 px 的呼吸空间，又保证了时间电量的即时可读性。
     - **顶部收纳备选**：将时间与电量移至顶部弧形栏的两端（10 点钟方向显示电量，2 点钟方向显示时间，12 点钟显示章节名），完全腾空 3 点与 9 点的横向排版通道。

## 核心专题修复：侧边时间与电量弧度几何重构

### 1. 原算法问题根因剖析

此前用户反馈“时间显示的弧度感觉不太对”，其技术原因并非简单的极坐标公式错误，而是由于**字体排印的字符物理宽度不均与对齐基准偏差**引发的视知觉反向凹陷：
- 原代码采用 `Paint.Align.CENTER`，算法将每一个字符的几何中心点置于圆弧 $x = cx + R \cos\theta$ 上。
- 时间格式为 `"14:35"`，其中第 3 个字符为冒号 `':'`。在等宽或比例字体中，冒号是**极窄字符**（宽度仅约 3~4 px），而两侧的数字是**全宽字符**（宽度约 14~18 px）。
- 由于字符以几何中心点居中对齐，全宽数字的墨水向右延伸了 7~9 px，而冒号仅向右延伸了 1.5~2 px。
- 在 5 个字符微小的 $17^\circ$ 角跨度下，弧度在横向产生的曲率位移总量仅约 2.6 px。宽字符比冒号向外多出的 5 px 宽度完全掩盖了曲率，导致**中间冒号处的视觉右边缘向内塌陷凹陷**。
- 人眼对连续边缘的“完形轮廓（Gestalt Contour）”极其敏感，感知到的是冒号凹陷、上下数字凸出的锯齿断裂，从而产生“弧度错误/扭曲不自然”的视觉感受。

### 2. 外轮廓相切对齐几何解法

将几何中心居中算法彻底重构为**外轮廓同心圆相切算法**：
- **右侧 3 点钟方向时间**：
  - 绘制对齐方式切换为 `Paint.Align.RIGHT`；
  - 绘制横坐标严格设为外同心圆弧上的极坐标点：$x = (cx + arcRadius \cdot \cos\theta)$；
  - 无论字符是宽数字还是窄冒号，其**最右侧视觉外边缘强制严格相切于同心圆弧**；冒号向内缩进在其自身左侧，不再破坏右侧平滑圆弧的外轮廓；
  - 补充 ASCII 冒号垂直居中微调（向下修正 0.5 dp），消除部分系统字体中冒号基线偏高的悬空感；
- **左侧 9 点钟方向电量**：
  - 绘制对齐方式切换为 `Paint.Align.LEFT`；
  - 绘制横坐标设为左外同心圆弧极坐标点：$x = (cx + arcRadius \cdot \cos\theta)$；
  - 所有字符的最左侧边缘严格相切于左圆弧；
- **角跨度微调**：
  - 步进角优化为 `angleStepRad = ((charSpacingPx * 1.05f) / arcRadius)`，使 5 字符在侧边形成自然、饱满、肉眼清晰可辨的优美贴边微弧。

## 进阶优化全景规划（六大维度）

### 维度一：排版系统与个性化微调

1. **行间距（Line Height）多档调节**：
   - 现状：当前写死为 `1.45f`。
   - 规划：在菜单中提供“紧凑 (1.25x) / 适中 (1.45x) / 宽松 (1.65x)”三档设置。大字号搭配紧凑行距减少频繁滚屏，小字号搭配宽松行距减少眼部疲劳。
2. **正文阅读即时进度微光常驻指示**：
   - 现状：阅读过程中无法感知全书进度百分比，必须退出到书架才能查看。
   - 规划：在正文底部的渐变暗区中，以 9 sp 微光字号常驻居中显示 `第 12/86 章 · 35%`，静态阅读时降低 Alpha，滚动或转动表冠时微亮。
3. **首行缩进与段落样式**：
   - 规划：支持“传统缩进（空两格 + 双换行）”与“现代段落间距（空行无缩进）”模式切换，满足不同用户的版式习惯。

### 维度二：手表专属人机交互进阶

1. **点按仿真翻整屏模式（Page Flip / Tap-to-Turn）**：
   - 现状：目前仅支持平滑连续滚屏。在走路或颠簸场景下，滑动手势容易失准。
   - 规划：支持“点按翻页”模式（轻按上半屏回退一屏，轻按下半屏推进一屏）。
2. **物理表冠整屏步进档位**：
   - 现状：表冠单格转动固定滚动 40 px（约 1.5 行）。
   - 规划：增加表冠滚动灵敏度选项（微调 40 px / 翻半屏 / 翻整屏），实现类似实体电子书按键的干脆翻页手感。
3. **防误触阅读锁（Reading / Water Lock）**：
   - 现状：衣袖摩擦或出汗容易造成误触翻页或误退页面。
   - 规划：菜单中增加“锁定”功能；开启后屏蔽一切屏幕手势，仅响应“物理表冠翻页”与“长按 2 秒解锁”。
4. **单击与双击交互习惯优化**：
   - 规划：优化为“单击呼出/收起沉浸控制面板与进度”、“双击开启/暂停自动滚屏”，消除当前单击误开自动滚屏的不适感。

### 维度三：电子书解析引擎与格式进阶

1. **EPUB 多级目录树层级展示**：
   - 现状：目前 NCX / Nav TOC 解析后直接扁平化为一维数组，丢失了“卷 / 篇 / 章”的分层。
   - 规划：在数据模型中记录 `level/depth` 层级，在目录列表中增加缩进与卷名加粗，避免大部头小说目录结构混乱。
2. **EPUB 关键插图查看**：
   - 现状：HTML 标签过滤时直接剥离了 `<img>` 标签。
   - 规划：将 `<img>` 替换为胶囊占位 `[查看插图]`，点击可呼出全屏图片浏览器，支持单指拖拽缩放。
3. **EPUB 脚注/译注（Footnotes）弹窗即阅**：
   - 规划：识别正文内的锚点 `<a href="#fn...">` 脚注，点击时在底部弹出轻量悬浮气泡展示注释释义。
4. **TXT 复杂章节前缀识别扩展与 Markdown（.md）支持**：
   - 规划：扩充纯数字序号（如 `001 章节名`、`1. 开始`）匹配，增加 `.md` 格式直读支持。

### 维度四：局域网 Wi-Fi 传书的双向管理能力

1. **Web 端“双向管理”：查看、下载与批量删除手表内书籍**：
   - 现状：目前传书网页仅支持向手表单向上传。
   - 规划：
     - 在 Web 端传书界面下方增加“手表已存书库”列表；
     - 提供 `GET /books`（获取书单）、`DELETE /books?name=...`（删除书籍）、`GET /download?name=...`（导出书籍）等原生 HTTP 接口；
     - 用户在手机或电脑浏览器上一目了然地查看手表存储空间、批量清理已读书籍。
2. **传输过程常驻后台唤醒锁（WifiLock / WakeLock）**：
   - 规划：在大文件传输过程中持有唤醒锁，防止部分手表的深度省电机制在息屏后切断 Wi-Fi 连接。

### 维度五：低功耗与续航优化（Smart Watch Lifecycle）

1. **Wear OS 低功耗微光常亮（Ambient Mode / AOD）适配**：
   - 现状：阅读时使用 `FLAG_KEEP_SCREEN_ON`，超时前始终处于高刷全彩状态。
   - 规划：
     - 增加常亮超时分级选项（1分钟 / 3分钟 / 5分钟 / 永久常亮）；
     - 支持接入 Wear OS 微光模式：手腕下垂时自动降低帧率、将所有彩色转为单色暗灰并隐藏平滑渐变，极限发挥 AMOLED 纯黑 0 功耗特性。
2. **手腕姿态感知与息屏即时冻结**：
   - 规划：监听系统息屏或传感器事件，放低手腕时立即冻结所有 Choreographer 帧循环与后台协程。

### 维度六：代码工程规范与整洁度（Clean Architecture）

1. **清理 FileHelper.kt 中的 SharedPreferences 遗留废弃代码**：
   - 现状：项目持久化已全面迁移至 `DataStoreManager.kt`，但 `FileHelper.kt` 中仍残留了 12 个读写旧 `SharedPreferences` 的死代码。
   - 规划：彻底清理无用函数，精简代码体积并消除维护混淆。
2. **优化 EpubParser 正文格式化内存分配**：
   - 现状：`EpubParser.extractFormattedTextFromHtml` 中仍使用 `content.split('\n')` 分配字符串数组。
   - 规划：对齐 TXT 模块的单趟就地字符扫描与 StringBuilder 拼接机制，消除大章节排版时的中间对象创建。
